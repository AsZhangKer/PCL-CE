## 💻 支持平台

| 操作系统 | 支持情况 | 环境要求 |
|---|---|---|
| Windows 10 1809 (17763) 或更高 | ✅ 完整支持 | [.NET 10 Desktop Runtime](https://get.dot.net/10) |
| Windows 8 - Windows 10 1809 (17763) | ⚠️ 理论能跑，酌情提供社区支持 | [.NET 10 Desktop Runtime](https://get.dot.net/10) |
| Windows 7 或更低版本 | ❌ 不支持 | / |

**✅ 完整支持**：尽可能提供一切相关支持，但必须确保启动器为最新版本。

**⚠️ 理论能跑，酌情提供社区支持**：PCL CE 应该可以在这些平台上运行，但不保证功能完全可用。你可能需要升级到完整支持的系统版本以获得进一步社区技术支持。

**❌ 不支持**：PCL CE 在这些平台的可用性较低，甚至压根打不开。请升级操作系统以使用 PCL CE。

**⚠️ 仅跨平台开发支持（交叉编译）**：PCL CE 的源代码可以在 macOS 与 Linux 平台编译，但无法直接运行。作为开发者，你可以在这些平台上进行开发，然后将编译产物转移到 Windows 系统测试。

**注**：    
社区仅对最新版本的启动器提供支持。    
取决于部分问题的特殊性（如系统不完整），有时你仍然必须升级操作系统以继续获得支持。    
PCL CE 始终建议使用最新版本的操作系统以获得最佳体验。    
你仍然可以尝试在不受支持的系统上使用 PCL CE，但可能会遇到很多额外问题。

# 🗺 项目结构与文件关系

> 本节面向开发者，说明本仓库（**PCL Ker** 分支）的代码组织、文件依赖与关键调用链。
> 上文是产品介绍，本节只回答三个问题：**代码在哪、谁引用谁、一次操作会走过哪些文件。**

## 1. 工程组成

| 目录 | 类型 | 目标框架 | 作用 |
|---|---|---|---|
| `Plain Craft Launcher 2/` | WPF 应用（`WinExe`） | `net10.0-windows` | 启动器外壳：窗体、页面、业务模块。`RootNamespace = PCL`，`StartupObject = PCL.Program` |
| `PCL.Core/` | 类库（`UseWPF=true`） | `net10.0-windows` | 与界面弱相关的核心能力：生命周期、配置、日志、网络、Java、身份认证模型、主题与通用控件 |
| `PCL.Core.SourceGenerators/` | Roslyn 增量源生成器 | `netstandard2.0` | 编译期生成：配置属性、依赖注入、生命周期布线、密钥常量 |
| `PCL.Core.Test/` | MSTest 单元测试 | `net10.0-windows` | 只引用 `PCL.Core`；在 `.slnx` 中显式 `Project="false"`，不参与主解决方案构建 |

依赖方向（箭头指向被依赖方）：

```
Plain Craft Launcher 2 ──ProjectReference──▶ PCL.Core
PCL.Core               ──Analyzer─────────▶ PCL.Core.SourceGenerators
PCL.Core.Test          ──ProjectReference──▶ PCL.Core
```

**关键约束**：`PCL.Core` 不反向引用 WPF 壳。`FormMain`、`Page*`、`ModMain` 这些全局静态类全部留在壳里，`PCL.Core` 只提供能力与基类。加新功能时先想清楚该放哪一层，别让 Core 反向依赖 UI。

## 5. 启动链路

```
Program.Main                                   ← 唯一入口（[STAThread]）
 ├─ 注册 ApplicationService / MainWindowService 的 Loading 委托（延迟创建 WPF 对象）
 └─ Lifecycle.OnInitialize()
      ├─ BeforeLoading  → 单例检测、提权、CLI 参数
      ├─ Loading        → 日志、Paths、系统信息、配置初始化
      ├─ Loaded         → Application._ApplicationStartup()（一次性初始化 + 首屏）
      ├─ WindowCreating → 创建 FormMain
      ├─ WindowCreated  → _ShowEnvironmentWarning()、主题刷新、首启弹窗
      ├─ Running        → 后台服务（依赖检查、遥测等）
      ├─ Closing / Exiting → 保存状态、停止托管服务
```

生命周期枚举顺序：`Manual → BeforeLoading → Loading → Loaded → WindowCreating → WindowCreated → Running → Closing → Exiting`。
服务类用 `[LifecycleService(状态, Priority = n)]` 标注，生成器把它接进流程。

**页面切换**：`FormMain.PageType`（主页 `Launch` / `Download` / `Setup`）+ `PageSubType`（副页面下标）+ `PageStackData` 组成导航栈。`PageSubType` 的数值**必须与对应 `StackPanel` 的子元素下标一致**，否则点错页面。

## 6. 游戏启动链路

`ModLaunch.McLaunchStart(options)` 必须在 UI 线程调用，内部构造 `LoaderCombo` 阶段链：

```
预检测 (McLaunchPrecheck)
 ├─ 获取 Java        McLaunchJava            权重 4
 ├─ 登录            mcLoginLoader（已有则跳过）
 ├─ 补全文件        ModDownload.DlClientFix 权重 15
 ├─ 生成启动参数    McLaunchArgumentMain     权重 2
 ├─ 解压 Natives    McLaunchNatives          权重 2
 ├─ 启动前处理      McLaunchPrerun           权重 1
 ├─ 自定义命令      McLaunchCustom           权重 1
 ├─ 启动进程        McLaunchRun              权重 2
 ├─ 等待游戏窗口    McLaunchWait             权重 1
 └─ 收尾            McLaunchEnd              权重 1
```

参数拼接在 `ModLaunch.LaunchArgument`（内部类，`new LaunchArgument(instance)`），JVM 参数与游戏参数分开累积。

## 7. 下载链路

```
页面 (PageDownload*) → ModDownload.DlXxxList / DlClientFix
   → ModLoader.LoaderTask / LoaderCombo（进度、取消、重试一律走 Loader）
      → ModNet（Facade）/ Requester（HTTP，含签名）
         → FileDownloader（NuGet Downloader，分块并行）
            → 落盘 + DownloadFile 进度回填
```

- 镜像源切换在 `ModDownload.DlSource`。
- `PCL.Core/IO/Download/NDl*` 是正在设计的新下载抽象，**尚未接入调用链**，改下载行为请动 `FileDownloader` / `ModNet`。

## 8. 配置与密钥

### 配置

`Config` 是 `partial class`，真正的属性由 `PCL.Core.SourceGenerators/ConfigGenerator.cs` 在编译期生成：

```csharp
[ConfigGroup("Launch")] partial class LaunchConfigGroup
{
    /// <summary>独立设置的启动参数预设</summary>
    [ConfigItem<int>("LaunchArgumentIndieV2", 4, ConfigSource.Local)]
    public partial int IndieSolutionV2 { get; set; }
}
```

- 分组挂在 `Config.Preference` / `Config.Launch` / `Config.Download` / `Config.Instance`（按实例分文件）等。
- `ConfigSource` 决定落盘位置：`Local`、`SharedEncrypt`（加密）、`GameInstance`（写进实例目录）。
- 存储后端在 `App/Configuration/Storage/`，`ConfigStorage.Access` 并发访问有锁保护（早期无锁版本会直接崩进程）。

### 密钥注入

`.env.local` → 编译期环境变量 → 源生成器 → `PCL.Core.dll` 内的常量：

```
.env.local ($env:PCL_MS_CLIENT_ID = "...")
   │  build.ps1 / package.ps1 用 Invoke-Expression 导入当前进程
   ▼
编译器进程环境变量（必须有 PCL_WRITE_SECRET 作为开关，且变量名以 PCL_ 开头）
   │  EnvironmentInteropGenerator 在编译期读环境，生成 SecretDictionary
   ▼
EnvironmentInterop.GetSecret("MS_CLIENT_ID")  →  Secrets.MSOAuthClientId
```

因此：**只要改了密钥，就必须重新编译**；直接 `dotnet build` 不会加载 `.env.local`，`PCL_*` 常量会留空。这也是 `build.ps1` 先执行 `dotnet build-server shutdown` 的原因——常驻编译器进程会沿用旧环境，导致注入静默失败。

当前使用的键名：`PCL_WRITE_SECRET`（开关）、`PCL_MS_CLIENT_ID`、`PCL_CURSEFORGE_API_KEY`、`PCL_NAID_CLIENT_ID`、`PCL_NAID_CLIENT_SECRET`。

凭据优先级：`Config.Preference.Theme.MsClientId`（设置界面可填）> 编译期注入 > 仅 Debug 生效的运行时环境变量。

## 9. 构建与打包

```powershell
# 日常开发（Debug）
./build.ps1 -Configuration Debug

# 出包（Release，输出到 .\artifact\PCL Ker.exe）
./package.ps1 -Configuration Release

# 清理
./clean.ps1
```

注意事项：

1. **不要用裸 `dotnet build`**，否则 `.env.local` 不生效，ClientID / CurseForge Key 会是空串。
2. **程序集名固定为 `Plain Craft Launcher 2`**。仓库内有 7 处用 `pack://application:,,,/Plain Craft Launcher 2;component/...` 定位图片与图标资源（如 `Basics.GetAppImagePath`），改名会导致资源加载失败。对外文件名由 `package.ps1` 在 publish 后重命名为 `PCL Ker.exe` 实现。
3. 产物是**单文件、依赖框架**（`--no-self-contained`），目标机需安装 .NET 10 桌面运行时。
4. **不要放在 `C:\Program Files`**：日志写在与 exe 同级的 `PCL\Log\` 下，需要写权限。
5. 运行时目录：`PCL/`（exe 同级，实例与日志）、`%APPDATA%\PCLCE`（共享配置）、`%LOCALAPPDATA%\PCLCE`（大文件缓存）、`%TEMP%\PCLCE`（临时文件）。Debug 构建这几个名字都带 `_Debug` / `PCLCE_Debug` 后缀，可与正式版共存。

## 11. 常见坑

| 现象 | 原因 / 处理 |
|---|---|
| 登录报 403 `Invalid app registration` | ClientID 未获 Mojang 白名单，不是代码问题。申请入口 `https://aka.ms/mce-reviewappid`，审批通过后关掉 `LoginMsLegacyShell` 并换回自有 ClientID |
| 新主题导致设置页选项错位 | 主题枚举必须追加在 `Custom = 10` 之后，否则 UI `SelectedIndex` 与枚举值错位 |
| 点了导航跳到别的页面 | `PageSubType` 数值必须与 `StackPanel` 子元素下标一致 |
| 弹窗里的换行不显示 | XAML 文本用 `&#xA;`，不要写 `\n` |
| 启动器卡死好几秒 | 实例目录扫描跑在 UI 线程；一律 `Task.Run` + 缓存 |
| 改了 `.env.local` 但没生效 | 未重新编译，或未关掉常驻编译器（`dotnet build-server shutdown`） |
| 图片/图标 404 | 程序集被改名，`pack://` URI 失效 |
